Locked design system, re-studied from `dailydispatch.app` on **2026-07-19**.

**Read this before touching any page's visual layer.**

## Reference (locked)

- **URL:** https://www.dailydispatch.app/?ref=onepagelove
- **Visual study date:** 2026-07-19 (browser-captured at 1440×900 desktop + 375×812 mobile, fullPage screenshots)
- **What it actually is:** a daily-briefings newspaper product, framed as "intelligence for serious information consumers." Editorial-newspaper aesthetic, not minimalist SaaS. Multi-section page (masthead, lede, accordion by source-type, italic serif pull-quote, FAQ, crossword, footer).

We are deliberately translating that "morning paper for serious people" DNA into an N2 daily mock exam product. The framing: *JLPT N2 daily mock = the morning paper for serious Japanese learners*. The reference's seriousness, density, and editorial ritual are the design target — not a "minimalist study tool" look.

---

## Genre

**Editorial-newspaper / daily-ritual hybrid.** Dark muted canvas, warm off-white newspaper cards floating on top, serif display type for masthead + section headings, overlapping phone mockup on the landing page. Calm but not minimalist. Dense but not noisy.

## Typography

### Display face — **Source Serif 4** (Latin) + **Noto Serif JP** (CJK)

Used for:
- The masthead H1 (`TODAY'S N2 MOCK` / `本日の模擬試験`)
- Section H2s (`Your progress`, `Today's revision`, etc.)
- The issue-meta strip (publication name in italic, day-of-month, year digits)
- Italic pull-quotes
- Japanese kanji display headings

Loaded via `next/font/google`:
```ts
const sourceSerif = Source_Serif_4({
  subsets: ['latin'],
  weight: ['400', '500', '600', '700'],
  style: ['normal', 'italic'],
  variable: '--font-serif',
  display: 'swap',
});

const notoSerifJP = Noto_Serif_JP({
  subsets: ['latin'],
  weight: ['400', '500', '600', '700'],
  variable: '--font-serif-jp',
  display: 'swap',
});
```

### Body / UI face — **Noto Sans JP** (kept)

Used for:
- Body text on the card (passage text, lede, button labels)
- All UI chrome (streak badge, progress dots, form inputs, option buttons)
- Meta labels, timestamps, navigation

Weights: 400 (body), 500 (labels), 700 (numeric score, very few cases).

Loaded via `next/font/google`:
```ts
const notoSansJP = Noto_Sans_JP({
  subsets: ['latin'],
  weight: ['400', '500', '700'],
  variable: '--font-sans',
  display: 'swap',
});
```

### Hierarchy rules

| Element | Face | Size (desktop / mobile) | Weight | Other |
|---|---|---|---|---|
| H1 / masthead | serif | 64px / 40px | 600 | letter-spacing -0.02em, line-height 1.0, ALL CAPS for English only |
| H2 / section | serif | 32px / 24px | 600 | letter-spacing -0.01em, line-height 1.1, sentence case |
| H3 / sub-section | serif | 20px / 18px | 500 | line-height 1.25 |
| Body (UI / lede) | sans | 16px / 15px | 400 | line-height 1.55 |
| Passage text | sans | 15px / 15px | 400 | line-height **1.9** (dense Japanese reading) |
| Meta / labels | sans | 12px / 11px | 500 | uppercase, letter-spacing 1.2px, color text-3 |
| Issue-meta day | serif | 40px / 28px | 500 | letter-spacing -0.02em |
| Issue-meta month | serif | 12px / 10px | 500 | uppercase, letter-spacing 1.5px, color text-2 |
| Issue-meta center | serif italic | 22px / 16px | 500 | letter-spacing -0.01em |

### Phone mockup (landing `/` only)

A decorative element, NOT a real screenshot. Overlaps the bottom-right corner of the newspaper card.

- Position: `absolute; bottom: -56px; right: -64px;`
- Tilt: `transform: rotate(8deg);`
- Z-index: 2 (above card)
- Width: ~200px, aspect-ratio: 9/19 (phone-like)
- Bezel: `--bg-deep` rounded rect
- Screen content: a stylized preview of "today's mock" — small `N2 Daily Mock` header + 1 question stub + 4 option dots
- Hidden on `<768px` (decorative; degrades gracefully)

### Issue-meta strip (top of every card)

Three-column row, evenly spaced across the card width.

```
[19]      N2 Daily Mock          [20]
[JUL]                          [26]
```

- All in serif. Tight letter-spacing.
- Day (left): large number above, month abbreviation below, both `--text` color
- Center: publication name in serif italic, `--text-2` color
- Right: year split into two stacked digits, `--text` color
- Below the strip: 1px `--hairline` divider spanning the full inner width

### Auth-gated page chrome (inside the newspaper card)

The same newspaper card composition as the landing, but:

- Card content is the page-specific UI (question / progress / revision / result)
- Streak badge sits at the top-left of the card body (below the issue-meta strip), small pill: `🔥 5 day streak` in sans 12px, `--text-3` color
- Progress dots sit below the issue-meta strip on `/today` only (5 small circles, current = `--accent` ring)
- Multi-section content can stack below: each section separated by a hairline divider, each prefixed by a serif H2 with optional accent dot before it

### Mobile (`<768px`)

- Card width: `calc(100vw - 32px)`, max 480px
- Phone mockup: hidden
- H1: scaled to 40px (from 64px)
- Issue-meta day/year digits: scaled to 28px (from 40px)
- All section headings: scaled per hierarchy table

## Components (locked)

These live in `~/projects/japanese-n2/components/`. The cron should USE them, not reimplement them per page.

### `<IssueMeta />`
Three-column top-of-card row. Server-rendered with today's JST date. Props: `{ day?: number; month?: string; center?: string; yearTop?: string; yearBottom?: string; }` — all defaulted to today.

### `<TiltedCard children ... />`
Wraps children in the newspaper card composition. Props: `{ tilt?: number; shadow?: boolean; }`. Server-rendered, no client state. Use this as the OUTERMOST element of every page's main content. (Class name `.tilted-card` + component name `TiltedCard` retained as legacy — the rotation transform was removed 2026-07-20 per Jackson; rename in a future pass if it keeps bothering.)

### `<PhoneMockup />`
The decorative phone overlapping the landing card. Server-rendered. Pure CSS + inline SVG content for the screen preview. NOT interactive. Only render on `/`.

### `<PullQuote text attribution? />`
Serif italic centered quote with hairline rule above + below. Use sparingly — at most one per page, usually only on result / progress pages for encouragement.

### `<StreakBadge count />`
Small pill, top-left of the card body, fire emoji + count + " day streak". Sans 12px, color `--text-3` on the warm card surface.

### `<ProgressDots total current answered[] />`
5 small circles (configurable `total`). Filled = `--text-3`, hollow = `--border`, current = `--accent` ring (2px).

### `<OptionButton state onClick label />`
Default: `--surface` + 1px `--border`. Selected: `--accent` 2px border + `--accent-soft` background. Never solid `--accent` fill — too loud for the editorial genre.

### `<ResultNote />`
`<details>` collapsed by default; summary: "why the others were wrong". Expands to show all 4 options' notes; correct in `--correct-soft`, wrong in `--wrong-soft`.

### `<PinnedPassage />`
`surface-2` background, `position: sticky; top: 16px;` while the question it belongs to is being answered. Sans 15px body, line-height 1.9 (dense Japanese reading).

## What NOT to do

- No light off-white bg as the page surface. The dark olive IS the canvas. Cards sit on it.
- No sans-only H1 / H2 / masthead. Serif display is mandatory for all major headings.
- No heavy shadows. Use `--shadow-card` only.
- No pill-shaped CTAs (`border-radius: 9999px`). Buttons are sharp at 8px.
- No italic headers (Hallmark rule).
- No fabricated stats — streak count comes from real attempt data only.
- No neon accents. The only saturated color is the deep-green `--accent`.
- No flat-centered hero with no composition. The warm off-white newspaper card on the dark canvas is the genre marker — lose that, lose the reference. (Card tilt removed 2026-07-20: the editorial-briefing tilt read as "why is my exam tilted" on a daily-mock exam product. The card composition itself — warm surface on dark canvas, asymmetric phone-mockup overlap, serif masthead — is what carries the genre, not the rotation.)
- No emoji as primary UI. Streak badge is the one allowed spot.

## Lessons (the 2026-07-19 rewrite)

The 2026-07-16 study that originally populated this file misread dailydispatch.app as a minimalist SaaS reference. It locked the wrong DNA: light off-white bg, sans-only, 640px max-width, "calm and quiet, no second display face." 25 cron passes tightened that wrong target between 2026-07-19 01:00 and 13:30 JST.

The 2026-07-19 browser-based re-study captured the actual reference:

- **Background:** dark olive / forest-green (~#3A3D2F), full-bleed. NOT off-white.
- **Hero composition:** warm off-white card tilted ~3° counter-clockwise on the dark canvas, with a phone mockup overlapping the bottom-right. (Tilt later removed 2026-07-20 — see §What NOT to do above. The straight-card composition + dark canvas + phone overlap + serif masthead is what carries the genre.)
- **Display type:** giant classical serif (Source Serif 4 / GT Sectra class), ALL CAPS for English masthead. NOT sans-only.
- **Multi-section newspaper page** below the hero: industry/trend/social accordion, italic serif pull-quote, FAQ, crossword, footer. NOT a single minimal hero.

**This rewrite is the result of that re-study.** All future passes must:

1. **Browser-screenshot both sites first** (skill Step 1). curl HTML is not visual evidence.
2. **Treat the screenshots as the source of truth**, not the prose in this file. The prose describes; the screenshots show.
3. **Reference this file for tokens + rules**, but verify against a fresh screenshot if anything looks off.
4. **Apply DNA to ALL pages in scope.** Convergence on `/` alone is not enough — the build is multi-page, so the design system must hold across all pages.

**Operating rule (the lesson, in one line):** *Trust visual evidence over verbal description, every time.*

### Why performance is stuck at 90-93 and what the real ceiling is

The performance ceiling is the **Supabase SSR session fetch blocking every server-rendered page**. `RootLayout` is an `async` server component that calls `await supabase.auth.getSession()` before rendering any HTML. Architecture-level fixes required to break through to 95+:
1. **Deferred auth check**: Move `getSession()` from `RootLayout` to a client component that renders after the page shell arrives — the server sends the HTML shell immediately, browser paints, then the client fetches the session and hydrates auth-gated content. Requires a loading-state / Suspense boundary.
2. **Edge runtime for middleware**: Move middleware to Edge Runtime (`export const runtime = 'edge'`) — eliminates cold starts on auth checks.
3. **Supabase Edge Functions**: Move session refresh to a Supabase Edge Function with faster cold starts than Vercel's Node.js serverless.
4. **`@next/font` font subsetting**: Pre-subset Noto Sans JP and Noto Serif JP to the JIS character set to reduce woff2 size (~300KB → ~80KB), directly improving LCP.
